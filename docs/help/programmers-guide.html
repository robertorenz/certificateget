ValidationChoosing a validation method

Before issuing, the certificate authority checks that you control every name, with an HTTP request to the domain or a TXT record in its DNS. Pick the method per certificate on New certificate.

MethodWhen to use itNeeds
HTTP (built-in server)Run the app on the server the domain points to. It answers on port 80 for a few seconds, without IIS.Port 80 free on this PC and reachable from the internet. No administrator rights needed.
HTTP (web root)A web server (IIS, Apache, nginx) already serves the site. The app writes the challenge file into its folder.Write access to the site's root folder, local or UNC path. Adds a web.config for IIS.
DNS (manual)Works anywhere, and for wildcards. You add the TXT records yourself; the app checks them before validating.Access to the DNS control panel for every request and renewal.
DNS (Cloudflare)Creates and removes the TXT records through the Cloudflare API.An API token with Zone Read and DNS Edit.
DNS (Hostinger)Creates and removes the TXT records through the Hostinger API.An hPanel API token; the domain on Hostinger's name servers.
DNS (Constellix)Creates and removes the TXT records through the Constellix API (v4).An API key and secret key; a correct PC clock.
DNS (acme-dns)Works with any DNS host. One CNAME per domain, then no DNS changes and no DNS credentials on this PC.An acme-dns server (public or your own) and one CNAME for _acme-challenge.
DNS (DNS Made Easy)Creates and removes the TXT records through the DNS Made Easy API (v2.0).An API key and secret key; a correct PC clock.
DNS (Namecheap)Creates and removes the TXT records through the Namecheap API; every other record is written back unchanged.API access turned on and this PC's public IPv4 whitelisted.

Wildcards need DNS

A wildcard name can only be proved through DNS. HTTP methods are refused for wildcard certificates.

HTTP validation

The certificate authority requests http://<domain>/.well-known/acme-challenge/<token> on port 80, always port 80, from the internet. With HTTP — built-in web server the app listens on port 80 of this PC for the few seconds the check takes; the port must be free (stop IIS or use the web root method) and forwarded to this PC. Another port only helps behind a port-forward from 80. With HTTP — existing web site folder the app writes the token file into the site's folder (a local path or a UNC share), adds a web.config so IIS serves files without an extension, and removes everything afterwards.

DNS validation

The certificate authority looks up a TXT record at _acme-challenge.<domain>. Before asking it to check, the app queries the public resolvers from Settings until every record is visible, for up to the propagation wait (600 seconds by default). With DNS — manual TXT record you create the records at your DNS host from the dialog, which has copy buttons and a Check DNS now button. Delete the old records after the request; each request uses new values.

DNS provider APIs

The provider methods create the TXT records, wait for them, and remove only their own values afterwards. Enter the credentials in Settings → DNS and use the Test button next to them.

ProviderWhere to get the credentialsNotes

HostingerhPanel → Account (profile icon) → API.The domain must use Hostinger's name servers. Other records are not touched.
ConstellixEdit My Account → API Keys. The secret key is shown once, when the key is created.Requests are signed with the current time; the PC clock must be correct.
DNS Made EasyConfig → Account Information shows the API key and secret key.Signed with the current time, like Constellix.

acme-dns

acme-dns is a small DNS server that only answers _acme-challenge TXT queries. Use it when your DNS host has no API, or you do not want DNS credentials on this PC. On the first request for a domain the app registers it and shows one CNAME to create, for example _acme-challenge.example.com CNAME 8e5700ea-….auth.acme-dns.io. That one CNAME covers the domain and its wildcard. After that, renewals need no DNS changes. Registrations are listed in Settings, with Copy target and Remove.

Use your own acme-dns server in production

The public server auth.acme-dns.io is fine for testing. Anyone holding a registration's credentials can get certificates for that domain, so for production run your own and enter it under Settings → acme-dns server.

Certificate authoritiesLet's Encrypt and ZeroSSL

The app gets certificates from either of two ACME certificate authorities, chosen per certificate under Certificate authority on the New certificate page. The default for new certificates is set in Settings. Both issue free, trusted certificates valid for 90 days, for single names, several names or wildcards.

Let's EncryptZeroSSL
Test serverYes: Staging issues untrusted certificates with generous limitsNone: every request is a trusted certificate

Pick Let's Encrypt when you want to test a new setup on Staging first. Pick ZeroSSL when you have hit a Let's Encrypt rate limit, want the certificates listed in a ZeroSSL dashboard, or want a second authority to fall back on.

Setting up ZeroSSL

ZeroSSL only accepts ACME accounts that are bound to a ZeroSSL account. The app fetches the binding credentials from ZeroSSL once, when the ZeroSSL ACME account is first created, in one of two ways:

  • With a ZeroSSL API key (recommended). Sign in at zerossl.com, open Developer, copy the API Access Key and paste it into Settings → ACME accounts → ZeroSSL API key. The ACME account is then linked to your ZeroSSL account, and the certificates it issues appear in your ZeroSSL dashboard.
  • With the contact e-mail only. Leave the API key empty and fill in the contact e-mail on the certificate (or the default one in Settings). ZeroSSL creates an account for that address if it has none, or reuses the existing one.

After that, only the ACME account key in accounts\zerossl.json is used; the API key is not read again. To move to a different ZeroSSL account, change the key or e-mail and click Reset accounts in Settings. That resets the Let's Encrypt accounts too; they are created again automatically on the next request, and issued certificates are not affected.

No staging on ZeroSSL

Every ZeroSSL request issues a real, trusted certificate. To test a new validation method or DNS setup, run it once against Let's Encrypt Staging, then switch the certificate to ZeroSSL.

Switching a certificate to the other authority

Open the certificate, click Renew, change Certificate authority and request. The new files are added to the same certificate's history, the deployment targets stay as they are, and later renewals use the authority chosen last. The agent does not care which authority issued a certificate: it receives the same sources either way. Only fullchain-root differs, because it ends in that authority's root.

CertificatesCertificates, issuances and files

A certificate in the app is a definition: its names, validation method, authority, key type, PFX password and deployment targets. Each successful request adds an issuance, a dated folder with the files, to its history. Renew reuses the definition; the latest issuance is the one that is exported, installed and deployed.

  • A new private key for every issuance. Each request generates a fresh key of the chosen type; a key is never reused.
  • Files written: the required formats (certificate, key and chain in PEM), which exports and renewals are built from, plus the formats ticked under Settings → Files written for new certificates. Any other format can be made later with Export. The full list is in the Reference.
  • File names come from the first domain, with * written as wildcard: wildcard.example.com.pfx.
  • Output options in Settings apply to new issuances and exports: PKCS#8 or traditional .key, 3DES or AES-256 PFX, and the JKS password.

Expiry and renewal

The list and the totals at the top of Certificates count certificates as valid, expiring soon (within Settings → Warn when a certificate expires within, 30 days by default) or expired / not issued. Renewal is manual: Renew then Renew certificate. The app does not run in the background or on a schedule, so check it regularly, or renew all certificates that are expiring soon when you open it. Let's Encrypt no longer sends expiry e-mails.

DeploymentDeployment targets

A certificate can have any number of targets. After every issuance or renewal, each enabled target set to Deploy automatically receives the new files; the result shows on the target and in the activity log. A failed target does not affect the others or the issuance itself; fix it and click Deploy now.

SFTP / SSH targets

  1. Enter the Host, Port (22) and User, and choose Password or Private key file (with its passphrase, if any). Both are stored encrypted.
  2. Enter the Remote folder and the Files to upload: a file type and the remote name for each. {domain} in a name becomes the first domain and {name} the certificate's name. The HAProxy and nginx presets fill in a folder, files and command.
  3. Optionally a Command to run afterwards, run over SSH as the same user. The deployment fails if it exits with a non-zero code.
  4. Click Test connection. The first time, the app shows the server's SSH host key fingerprint; trust it and the app refuses any other key later. Forget host key clears it after a server is rebuilt.

Each file is uploaded as <name>.cg-upload and then renamed over the old one, so the server never reads half a file. Files holding the private key get mode 600, others 644. The file types are listed in the Reference.

StorageStore folder, secrets and activity log

Everything the app keeps is in the store folder (Settings → Store folder, default %LOCALAPPDATA%\CertificateGet\Store): certificates and their history, the ACME account keys and the activity log. Settings themselves are in %LOCALAPPDATA%\CertificateGet\settings.json. The layout is in the Reference.

  • Encrypted with Windows DPAPI for your Windows user: PFX passwords, ACME account keys, DNS tokens and keys, acme-dns passwords, SFTP passwords and key passphrases, agent API keys. Another Windows user, or another PC, cannot decrypt them; the app then creates a new ACME account and asks for the other secrets again.
  • Not encrypted: the private keys in the .key and .pem files, as on any web server. Keep the store out of cloud-synced folders and readable only by you.
  • Activity log: every request, validation, export, install, deployment and error, in activity.jsonl. The Activity log page searches and filters it and exports CSV.

Agent conceptsSlots, destinations and files

Three levels describe where a certificate goes on a server.

LevelWhat it isTypical count
SlotOne certificate as the server sees it. A deployment target in the app names one slot.One per certificate, for example reddin-wildcard.
DestinationOne program that uses the certificate: a folder and file names, or a TSplus import, plus what to restart.One per program instance.
FileA source (the format, such as fullchain) and the file name to give it.One to three per destination.

The app never decides folders or file names for an agent. It asks the agent which sources the slot needs and sends those. When you add a NetTalk instance or change a file name, you change agent.json on the server and nothing in the app.

One agent can hold many slots. Two certificates deployed to the same server are two slots in the same file, and two targets in the app (one on each certificate) pointing at the same agent URL.

ConceptsHow a deployment runs

The order matters when you write commands, so here it is exactly as the agent runs it.

1 · Ask

The app calls GET /api/slots/{slot} and gets the list of sources the slot needs.

↓
2 · Send

The app builds those files from the issued certificate and posts them in Base64 to /api/deploy, with the PFX password only when a pfx, p12 or encrypted-key is needed.

↓
3 · Admit

The agent re-reads agent.json, checks AllowedIps and the API key. Deployments run one at a time.

↓
4 · Write

For each destination in order: back up the current file, write the new one atomically. TSplus destinations import instead.

↓
5 · Services

Every RestartServices entry of the successful destinations, each service once, in the order first listed.

↓
6 · Programs

Every RestartPrograms entry (Windows), each executable once.

↓
7 · Commands

Each destination's Commands in order, with {folder} replaced, then the slot's own Commands.

↓
8 · Report

Every step, good or bad, goes back to the app's activity log and into agent.log.

Commands run after all restarts

A destination's Commands do not run right after its own files are written; they run after every destination has been written and every service restarted. If a command must happen before a restart, leave RestartServices empty and do both in one command, for example icacls … && net stop X && net start X.

When a step fails

A failed step does not stop the run. If writing a destination fails, that destination's restarts and commands are skipped, and the other destinations carry on. A failed restart or a command with a non-zero exit code is reported, and the next step still runs. The deployment is then marked failed in the app, with every step listed, so you can see which part worked.

ConceptsEditing agent.json on a live server

The agent reads agent.json again on every request. A new slot, destination or file name applies to the next deployment without a restart. Only Port is read at start-up; after changing it, restart the service and open the new port in the firewall.

A syntax error does not stop the service. Requests are refused with a clear message, which the app shows, until the file is fixed. check prints the line:

ERROR agent.json has a syntax error on line 14 (at $.Slots[0].Destinations[0].Folder):
        "Folder": "C:\Apps\Web\certificates",
Common causes: text not inside "quotes", curly quotes instead of straight ", a missing comma between items,
or a comma after the last item. Backslashes in Windows paths must be doubled (C:\\Apps).

FilesHow files are written

  • Atomically. Each file is written to <name>.cg-tmp and then renamed over the old one, so a program never reads half a file.
  • Folders are created when they do not exist.
  • Linux, new files: key material (combined, combined-keyfirst, encrypted-key, jks, k8s, key, p12, pfx) gets mode 600; other files get 644.
  • Linux, replaced files keep the owner, group, mode and SELinux label of the file they replace (chown --reference, chcon --reference). A Cockpit certificate set to root:cockpit-ws 640 stays that way.
  • Windows files inherit the folder's permissions.

FilesBackups

Before a file is replaced, the current one is copied into the agent's own folder, never next to the live files. HAProxy loads every file in its certificate folder, so a .bak there would be served too.

<agent folder>/backups/<slot>/<destination>/<yyyyMMdd-HHmmss>/<file>
C:\Program Files\CertificateGet Agent\backups\reddin-wildcard\NetTalk_-_Portal\20260927-031200\portal.crt

KeepBackups (default 5) is how many of those dated folders are kept per destination; 0 turns backups off. To roll back, copy the files from a dated folder back into place and restart the program, or run the destination's command by hand.

RestartsServices, programs and commands

RestartServices

On Windows, the service is stopped (waiting up to 90 seconds), then started (waiting up to 90 seconds for Running). On Linux, the agent runs systemctl restart <unit>. Each name is restarted once per deployment, even when several destinations list it.

Reload rather than restart where you can

A restart drops open connections. For HAProxy and nginx, leave RestartServices empty and use a Commands entry that checks the configuration and reloads, for example haproxy -c -f /etc/haproxy/haproxy.cfg && systemctl reload haproxy.

RestartPrograms

For programs that run on a desktop instead of as a service, such as a NetTalk server started from the Startup folder. For every running copy of the executable, the agent:

  1. notes its full command line and the Windows session (desktop) it runs in,
  2. asks it to close normally, as if its close button were clicked,
  3. ends it if it is still running after StopTimeoutSeconds (default 20),
  4. starts it again in the same session, as the same user, with the same command line,
  5. checks that it is still running three seconds later.

Several copies with different parameters each come back with their own parameters. A user must be logged on, at the console or in a disconnected RDP session, for a program to come back on a desktop. On unattended servers use automatic logon, or "StartIn": "Background" when no window is needed.

SecuritySecurity model

ProtectionHow it works
TLS onlyThe agent listens on HTTPS with its own certificate. The app pins its SHA-256 fingerprint on first connect, after you compare it with info, and refuses a different one later.
API keySent in the X-Api-Key header. The agent stores only its SHA-256 hash and compares it in constant time. A wrong key is logged and answered after a 1.5 second delay.
AllowedIpsWhen the list is not empty, only those addresses may connect (loopback is always allowed). Put the IP of the PC that runs CertificateGet here.
Request sizeBodies over 20 MB are refused.
One at a timeDeployments are queued, so two renewals never write the same files at once.

Protect the agent folder

It holds agent.json, the agent's TLS key and the backups, which contain private keys. Keep it readable by administrators or root only. Anyone who can edit agent.json can make the agent run a command as LocalSystem or root.

To rotate the API key, run newkey on the server and paste the new key into every app target that uses the agent.

NotesPlatform notes

Behaviour that belongs to the operating system or to the program receiving the certificate, found while running the agent on real servers.

SELinux and moved binaries

A file moved with mv keeps the SELinux label of the place it came from. A binary moved out of /tmp is labelled user_tmp_t, and systemd fails to start it with status=203/EXEC and no other message. install labels the agent bin_t; after an update copy with cp or run restorecon. The same applies to certificate files you move into place by hand, which is why the Cockpit command runs restorecon -F.

Copying the example file over agent.json

The shipped examples contain placeholders for ApiKeyHash and TlsPassword. The agent survives it: when the TLS password does not open agent-tls.pfx, it renames the old file to agent-tls.pfx.old-<time> and creates a new certificate (the app will ask you to trust the new fingerprint), and check reports the missing key. Copy only the Slots section from an example.

HAProxy loads every file in the crt folder

With crt /etc/haproxy/certs/, HAProxy loads each file in that folder and picks one by SNI. A stray backup or a half-written file there is loaded too, or stops HAProxy from starting. That is why the agent writes atomically and keeps backups elsewhere, and why the reload command runs haproxy -c first.

Cockpit reads the certificate as cockpit-ws

cockpit-tls runs as the cockpit-ws user, so the key (or the combined .cert) must be root:cockpit-ws with mode 640. Cockpit uses the last .cert/.crt file in alphabetical order in /etc/cockpit/ws-certs.d. After several failed starts systemd stops trying, which is why the command runs systemctl reset-failed before restarting the socket.

NetTalk reads its certificate at start-up

A NetTalk web server loads the certificate and key when it starts listening, so new files have no effect until the service or program restarts. Every NetTalk destination therefore needs a RestartServices or RestartPrograms entry.

TSplus needs a password on the PFX

CertificateManager.exe reads the password from certpassword.txt in its own folder and will not import a PFX without one. If the certificate has no PFX password in the app, the agent wraps it with a random password for the import. Both temporary files are deleted afterwards. Versions that use cert.jks expect the keystore password secret, the app's default.

Desktop programs and session 0

The agent runs as a service in session 0, which has no desktop. To bring a program back where the user can see it, it starts it in the user's session with that user's token. With nobody logged on there is no such session, and the program can only be started with "StartIn": "Background".
