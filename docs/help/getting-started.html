Volume 1

Getting Started

Build the agent, install it as a service on Windows or Linux, describe where the certificate goes, and connect the CertificateGet app to it.

Windows serviceLinux systemdHTTPS port 94435 steps

OverviewWhat the agent does

The agent is a small service you install on each server that uses a certificate. When the CertificateGet app issues or renews a certificate, it sends the files to the agent over HTTPS. The agent writes them where each program expects them, restarts what needs restarting, and reports every step back to the app's activity log.

CertificateGet

The desktop app on your PC issues or renews the certificate from Let's Encrypt.

↓
HTTPS :9443

The app asks the agent which files the slot needs, then sends exactly those. It checks the agent's pinned TLS fingerprint and sends the API key.

↓
Agent

A Windows service or systemd unit on the server. It reads agent.json, finds the slot and backs up the current files.

↓
Destinations

Files written into each folder with the names each program expects, or imported into TSplus.

↓
Restarts

Services, desktop programs and commands (for example systemctl reload haproxy), each once.

Use the agent on servers that need more than a file copy: several NetTalk instances with their own file names, TSplus, desktop programs that must be restarted on a user's desktop. For a single Linux box where an upload and one command are enough, the app's SFTP target works without installing anything.

Step 1Get the executables

Build both agents with the publish script in the repository root. They are self-contained single files, so the servers need no .NET runtime.

.\publish.ps1
# run\agent-windows\CertificateGet.Agent.exe   Windows servers (NetTalk, TSplus, IIS)
# run\agent-linux\CertificateGet.Agent         Linux servers (HAProxy, Cockpit, nginx), x64

Each output folder also gets README.md and agent.example.json. The example is for reading. Do not copy it over agent.json: it holds placeholders instead of the real key hash and TLS password.

Step 2aInstall on Windows

Do this on the server that runs NetTalk, TSplus or the other programs using the certificate.

  1. Copy the executable to a folder of its own. The agent keeps agent.json, its TLS certificate, the log and the backups next to the executable.
    New-Item -ItemType Directory "C:\Program Files\CertificateGet Agent" -Force
Copy-Item .\CertificateGet.Agent.exe "C:\Program Files\CertificateGet Agent\"
  2. Open PowerShell as administrator and run install. Add a port number if 9443 is taken.
    cd "C:\Program Files\CertificateGet Agent"
.\CertificateGet.Agent.exe install          # or: .\CertificateGet.Agent.exe install 9543
  3. Copy the three values it prints. The API key is shown only this once.
    Installed. Enter these in CertificateGet → certificate → Deployment → Add target → Agent:
  URL          https://WEB01:9443
  API key      q3ZtY0n8…Kd4      (shown once — store it now)
  Fingerprint  5E1B7C…90AF   (the app asks you to confirm this on first connect)
  4. Check the service. info prints the URL and fingerprint again at any time.
    Get-Service CertificateGetAgent
.\CertificateGet.Agent.exe info

What install changes on Windows

ItemDetail
ServiceCertificateGetAgent (display name CertificateGet Agent), delayed automatic start, runs as LocalSystem, restarted by Windows 60 seconds after a failure.
FirewallInbound rule CertificateGet Agent for the TCP port.
agent.jsonCreated with a sample slot, unless one already exists. The API key hash is stored, never the key.
agent-tls.pfxSelf-signed TLS certificate for the agent, valid 20 years. The app pins its SHA-256 fingerprint.

Step 2bInstall on Linux

For HAProxy, Cockpit, nginx and other Linux services. The agent runs as root because it writes under /etc and restarts services.

  1. Copy the binary to the server.
    scp run/agent-linux/CertificateGet.Agent admin@lb01:/tmp/
  2. Put it in its own folder. Use cp, not mv: on SELinux systems a file moved out of /tmp keeps a label that systemd refuses to run.
    sudo mkdir -p /opt/certificateget-agent
sudo cp /tmp/CertificateGet.Agent /opt/certificateget-agent/
sudo chmod +x /opt/certificateget-agent/CertificateGet.Agent
  3. Install. Copy the URL, API key and fingerprint it prints.
    cd /opt/certificateget-agent
sudo ./CertificateGet.Agent install         # or: sudo ./CertificateGet.Agent install 9543
  4. Open the port. Only one of these applies to your distribution.
    sudo ufw allow 9443/tcp                                                          # Ubuntu / Debian
sudo firewall-cmd --permanent --add-port=9443/tcp && sudo firewall-cmd --reload  # RHEL / Rocky / Alma / Fedora
  5. Check it is running.
    systemctl status certificateget-agent
sudo ./CertificateGet.Agent info
journalctl -u certificateget-agent -f          # live log; the same lines go to agent.log

What install changes on Linux

ItemDetail
systemd unit/etc/systemd/system/certificateget-agent.service, Type=notify, Restart=on-failure, enabled and started.
SELinuxWhen SELinux is enabled, the executable is labelled bin_t (semanage fcontext + restorecon, or chcon as a fallback).
FirewallNot touched. Open the port yourself (step 4).
Filesagent.json and agent-tls.pfx are created with mode 600.

Step 3Describe where the certificate goes

Open agent.json next to the executable and replace the sample slot. A slot is what a certificate in the app points to; each slot lists destinations, and each destination says which files to write where and what to restart. This one writes a certificate and key for one NetTalk service:

{
  "Port": 9443,
  "ApiKeyHash": "…left as install wrote it…",
  "AllowedIps": [],
  "TlsPfx": "agent-tls.pfx",
  "TlsPassword": "…left as install wrote it…",
  "KeepBackups": 5,
  "Slots": [
    {
      "Name": "example-com",
      "Description": "www.example.com for the NetTalk web server",
      "Destinations": [
        {
          "Name": "NetTalk web",
          "Folder": "C:\\Apps\\Web\\certificates",
          "Files": [
            { "Source": "fullchain", "FileName": "www.example.com.crt" },
            { "Source": "key",       "FileName": "www.example.com.key" }
          ],
          "RestartServices": [ "WebServer" ]
        }
      ]
    }
  ]
}

Then validate it. The agent reads the file again on every request, so no restart is needed (except after changing Port).

.\CertificateGet.Agent.exe check
Slot "example-com"
  • NetTalk web
OK — configuration looks good.

Ready-made files for NetTalk, HAProxy, Cockpit and TSplus are in the Template Guide; every field is in the Reference.

Windows paths in JSON

Every backslash is written twice: "C:\\Apps\\Web". A single backslash is a JSON syntax error, and check shows the line.

Step 4Connect the app

In CertificateGet, on the PC that issues the certificates:

  1. Open Certificates, select the certificate, and in the Deployment section click Add target.
  2. Choose CertificateGet Agent. Enter a Name (for example WEB01 NetTalk), the Agent URL (https://WEB01:9443) and the API key.
  3. Click Connect & list slots. The first time, a dialog shows the agent's TLS fingerprint. Compare it with the info output on the server and click Trust. The app then refuses any other certificate at that URL.
  4. Click the slot chip (for example example-com) to fill in Slot on the agent.
  5. Leave Enabled and Deploy automatically after every issuance / renewal ticked, then Save target.
  6. Click Deploy now to send the current certificate straight away.

These four volumes are also built into the app: click Help at the bottom of the sidebar, or press F1.

Step 5Check the first deployment

The app's Activity log shows one line per agent step. A successful run looks like this:

NetTalk web: wrote www.example.com.crt, www.example.com.key to C:\Apps\Web\certificates
Restarted service WebServer

On the server, the same lines are in agent.log next to the executable, and the previous files are in backups\example-com\NetTalk_web\<date-time>\. Check what the server now presents:

openssl s_client -connect www.example.com:443 -servername www.example.com </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -enddate

MaintenanceUpdate, move or remove the agent

Update on Windows

sc.exe stop CertificateGetAgent
Copy-Item .\CertificateGet.Agent.exe "C:\Program Files\CertificateGet Agent\" -Force
sc.exe start CertificateGetAgent

Update on Linux

sudo systemctl stop certificateget-agent
sudo cp /tmp/CertificateGet.Agent /opt/certificateget-agent/CertificateGet.Agent
sudo restorecon -v /opt/certificateget-agent/CertificateGet.Agent    # SELinux systems only
sudo systemctl start certificateget-agent

Remove or reinstall

uninstall removes the service and (on Windows) the firewall rule, and keeps agent.json, the TLS certificate and the backups. Running install again keeps the existing configuration and API key. If the TLS certificate is new (a fresh folder or another server), open the target in the app, click Forget fingerprint, and trust the new one on the next connect.
