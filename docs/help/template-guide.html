agent.jsonThe shape of the file

agent.json sits next to the executable. The top of the file is written by install and rarely changes; your work is in Slots. Each template below is one slot (or one destination) to paste into that list.

{
  "Port": 9443,                         // HTTPS port; restart the service after changing it
  "ApiKeyHash": "…",                    // written by install / newkey — do not edit
  "AllowedIps": [ "192.168.1.50" ],     // the PC running CertificateGet; [] = any
  "TlsPfx": "agent-tls.pfx",            // the agent's own TLS certificate
  "TlsPassword": "…",                   // written by the agent — do not edit
  "KeepBackups": 5,                     // dated backup folders kept per destination
  "Slots": [
    {
      "Name": "example-com",            // what the app's deployment target names
      "Description": "…",               // shown in the app
      "Destinations": [
        {
          "Name": "…",                  // shown in the log; also the backup folder name
          "Kind": "Files",              // Files (default), TSplus or TSplusJks
          "Folder": "…",                // created when missing
          "Files": [ { "Source": "fullchain", "FileName": "…" } ],
          "RestartServices": [],        // Windows service names / systemd units
          "RestartPrograms": [],        // Windows desktop programs
          "Commands": []                // cmd.exe on Windows, /bin/sh on Linux; {folder} = Folder
        }
      ],
      "Commands": []                    // run once, after all destinations
    }
  ]
}

Comments are for reading only

JSON has no comments. The // notes above explain the fields; the real file must not contain them. The templates below are plain JSON and can be pasted as they are.

After every change run check. Every field is described in the Reference.

WindowsNetTalk

A NetTalk web server reads a certificate file and a private key file, named in the WebServer procedure's SSL settings. Each instance commonly uses its own certificates folder with <domain>.crt and <domain>.key. Write fullchain as the certificate so browsers get the intermediate, write key as the key, and restart the instance, because NetTalk loads the files at start-up.

NetTalk settingSourceExample file
Certificate filefullchaincertificates\www.example.com.crt
Private key filekeycertificates\www.example.com.key
RestartRestartServices or RestartProgramsService name, or the path of the .exe

One NetTalk service

The service name is the Name column of Get-Service, not the display name.

{
  "Name": "www-example-com",
  "Description": "www.example.com for the NetTalk web server",
  "Destinations": [
    {
      "Name": "NetTalk web",
      "Folder": "C:\\Apps\\Web\\certificates",
      "Files": [
        { "Source": "fullchain", "FileName": "www.example.com.crt" },
        { "Source": "key",       "FileName": "www.example.com.key" }
      ],
      "RestartServices": [ "WebServer" ]
    }
  ]
}

Several NetTalk instances, one certificate

A wildcard certificate used by several NetTalk servers is one slot with one destination per instance, each with the file names that instance is configured with. The certificate is sent once and written three times.

{
  "Name": "reddin-wildcard",
  "Description": "*.reddinassessments.com for three NetTalk servers",
  "Destinations": [
    {
      "Name": "NetTalk - Assessments",
      "Folder": "C:\\Apps\\Assessments\\certificates",
      "Files": [
        { "Source": "fullchain", "FileName": "reddinassessments.com.crt" },
        { "Source": "key",       "FileName": "reddinassessments.com.key" }
      ],
      "RestartServices": [ "AssessmentsWeb" ]
    },
    {
      "Name": "NetTalk - Portal",
      "Folder": "D:\\Portal\\certs",
      "Files": [
        { "Source": "fullchain", "FileName": "portal.crt" },
        { "Source": "key",       "FileName": "portal.key" }
      ],
      "RestartServices": [ "PortalWeb" ]
    },
    {
      "Name": "NetTalk - Reports",
      "Folder": "D:\\Reports\\certificates",
      "Files": [
        { "Source": "fullchain", "FileName": "reports.reddinassessments.com.crt" },
        { "Source": "key",       "FileName": "reports.reddinassessments.com.key" }
      ],
      "RestartServices": [ "ReportsWeb" ]
    }
  ]
}

NetTalk running as a desktop program

When the server is started from a logged-on desktop instead of as a service, restart it with RestartPrograms. Every running copy is closed and started again with its own command line, on the same desktop.

{
  "Name": "api-example-com",
  "Description": "api.example.com, NetTalk server started on the desktop",
  "Destinations": [
    {
      "Name": "NetTalk - API (desktop program)",
      "Folder": "C:\\Apps\\Api\\certificates",
      "Files": [
        { "Source": "fullchain", "FileName": "api.crt" },
        { "Source": "key",       "FileName": "api.key" }
      ],
      "RestartPrograms": [
        { "Path": "C:\\Apps\\Api\\ApiServer.exe", "StopTimeoutSeconds": 30 }
      ]
    }
  ]
}

If the program must stay hidden and no one is logged on, add "StartIn": "Background". Details are in RestartPrograms.

LinuxHAProxy

HAProxy wants the certificate, the chain and the key in one PEM file, which is the combined source. Point the bind line at the folder, and HAProxy loads every file in it and picks one by SNI.

frontend https-in
    bind :443 ssl crt /etc/haproxy/certs/ alpn h2,http/1.1
    bind :80
    http-request redirect scheme https unless { ssl_fc }
    default_backend web

One certificate

{
  "Name": "example-com",
  "Description": "HAProxy on lb01",
  "Destinations": [
    {
      "Name": "HAProxy",
      "Folder": "/etc/haproxy/certs",
      "Files": [
        { "Source": "combined", "FileName": "example.com.pem" }
      ],
      "Commands": [ "haproxy -c -f /etc/haproxy/haproxy.cfg && systemctl reload haproxy" ]
    }
  ]
}

The command checks the whole configuration with the new file before reloading. If the check fails, the reload does not run, HAProxy keeps serving with the certificate it already has, and the app shows the error. reload keeps open connections; avoid RestartServices: ["haproxy"].

Several certificates in the same folder

Each certificate is its own slot with its own file name. Each certificate in the app gets a target pointing at its slot.

"Slots": [
  {
    "Name": "example-com",
    "Destinations": [
      { "Name": "HAProxy", "Folder": "/etc/haproxy/certs",
        "Files": [ { "Source": "combined", "FileName": "example.com.pem" } ],
        "Commands": [ "haproxy -c -f /etc/haproxy/haproxy.cfg && systemctl reload haproxy" ] }
    ]
  },
  {
    "Name": "example-org",
    "Destinations": [
      { "Name": "HAProxy", "Folder": "/etc/haproxy/certs",
        "Files": [ { "Source": "combined", "FileName": "example.org.pem" } ],
        "Commands": [ "haproxy -c -f /etc/haproxy/haproxy.cfg && systemctl reload haproxy" ] }
    ]
  }
]

LinuxCockpit

Cockpit takes its certificate from /etc/cockpit/ws-certs.d. It uses the last .cert or .crt file in alphabetical order; a .cert file holds the chain and key together, and a .crt file needs a .key file of the same name. The key must be readable by the cockpit-ws group.

Replace the certificate Cockpit already uses

If a certificate is already there, for example reddinassessments.cert, overwrite it with combined. The agent keeps its owner, group, mode and SELinux label, and the command sets them again for a first deployment.

{
  "Name": "Cockpit",
  "Folder": "/etc/cockpit/ws-certs.d",
  "Files": [
    { "Source": "combined", "FileName": "reddinassessments.cert" }
  ],
  "Commands": [ "chgrp cockpit-ws {folder}/reddinassessments.cert && chmod 640 {folder}/reddinassessments.cert && restorecon -F {folder}/reddinassessments.cert ; systemctl reset-failed cockpit.socket cockpit ; systemctl restart cockpit.socket ; systemctl try-restart cockpit" ]
}

Add a certificate next to the self-signed one

Otherwise write fullchain and key as 90-letsencrypt.crt and 90-letsencrypt.key. They sort after Cockpit's 0-self-signed.cert, so Cockpit picks them.

{
  "Name": "Cockpit",
  "Folder": "/etc/cockpit/ws-certs.d",
  "Files": [
    { "Source": "fullchain", "FileName": "90-letsencrypt.crt" },
    { "Source": "key",       "FileName": "90-letsencrypt.key" }
  ],
  "Commands": [ "chgrp cockpit-ws {folder}/90-letsencrypt.key && chmod 640 {folder}/90-letsencrypt.key && restorecon -F {folder}/90-letsencrypt.* ; systemctl reset-failed cockpit.socket cockpit ; systemctl restart cockpit.socket ; systemctl try-restart cockpit" ]
}

What the command does

PartWhy
chgrp cockpit-ws … && chmod 640 …The key must be readable by cockpit-tls, which runs as cockpit-ws.
restorecon -F …Resets the SELinux label. Not installed on Debian/Ubuntu; the ; after it lets the rest run anyway.
systemctl reset-failed cockpit.socket cockpitClears systemd's start limit after earlier failures, so the restart is not refused.
systemctl restart cockpit.socketCockpit is socket-activated; restarting the socket makes the next connection load the new certificate.
systemctl try-restart cockpitRestarts the running service only if it is running, and ends with exit code 0 so the step succeeds.

To see which certificate Cockpit will use:

sudo /usr/lib/cockpit/cockpit-certificate-ensure --check      # Debian / Ubuntu
sudo /usr/libexec/cockpit-certificate-ensure --check         # RHEL / Rocky / Alma / Fedora

WindowsTSplus

TSplus has two ways of taking a certificate, depending on the version. Both are a destination with a Kind and no files; the agent knows the paths.

KindTSplus versionWhat the agent does
TSplus15 and laterWrites a temporary PFX and certpassword.txt, runs C:\Program Files (x86)\TSplus\UserDesktop\files\cert\CertificateManager.exe /add <pfx>, deletes both.
TSplusJksVersions that use cert.jksBacks up and replaces C:\Program Files (x86)\TSplus\Clients\webserver\cert.jks (password secret, full chain), then runs UserDesktop\files\AdminTool.exe /webrestart.

TSplus 15 and later

{
  "Name": "tsplus-example-com",
  "Description": "remote.example.com for the TSplus web portal",
  "Destinations": [
    { "Name": "TSplus web portal", "Kind": "TSplus" }
  ]
}

Older TSplus with cert.jks

{
  "Name": "tsplus-example-com",
  "Description": "remote.example.com for an older TSplus (cert.jks)",
  "Destinations": [
    { "Name": "TSplus web portal", "Kind": "TSplusJks" }
  ]
}

The JKS password comes from the app's Settings (JKS keystore password). Leave it at secret; TSplus expects that value.

TSplus installed somewhere else

{ "Name": "TSplus (15+) on D:",   "Kind": "TSplus",    "TsplusCertFolder": "D:\\TSplus\\UserDesktop\\files\\cert" }
{ "Name": "TSplus (jks) on D:",   "Kind": "TSplusJks", "TsplusFolder": "D:\\TSplus" }

check confirms that CertificateManager.exe or the Clients\webserver folder is where the destination says.

Complete filesSeveral programs on one server

These are the example files shipped with the agent (agent.example.json in each build folder), printed here from the repository. The first puts one wildcard certificate into three NetTalk instances, one of them a desktop program, and into TSplus. The second serves HAProxy and Cockpit on one Linux machine.

Windows: NetTalk and TSplus

{
  "Port": 9443,
  "ApiKeyHash": "(created by: CertificateGet.Agent.exe install)",
  "AllowedIps": [ "192.168.1.50" ],
  "TlsPfx": "agent-tls.pfx",
  "TlsPassword": "(created automatically)",
  "KeepBackups": 5,
  "Slots": [
    {
      "Name": "reddin-wildcard",
      "Description": "*.reddinassessments.com for every NetTalk instance and TSplus on this server",
      "Destinations": [
        {
          "Name": "NetTalk - Assessments",
          "Folder": "C:\\Apps\\Assessments\\certificates",
          "Files": [
            { "Source": "fullchain", "FileName": "reddinassessments.com.crt" },
            { "Source": "key", "FileName": "reddinassessments.com.key" }
          ],
          "RestartServices": [ "AssessmentsWeb" ]
        },
        {
          "Name": "NetTalk - Portal",
          "Folder": "D:\\Portal\\certs",
          "Files": [
            { "Source": "fullchain", "FileName": "portal.crt" },
            { "Source": "key", "FileName": "portal.key" }
          ],
          "RestartServices": [ "PortalWeb" ]
        },
        {
          "Name": "NetTalk - API (desktop app, not a service)",
          "Folder": "C:\\Apps\\Api\\certificates",
          "Files": [
            { "Source": "fullchain", "FileName": "api.crt" },
            { "Source": "key", "FileName": "api.key" }
          ],
          "RestartPrograms": [
            { "Path": "C:\\Apps\\Api\\ApiServer.exe", "StopTimeoutSeconds": 20 }
          ]
        },
        {
          "Name": "TSplus web portal (TSplus 15+: PFX import)",
          "Kind": "TSplus"
        },
        {
          "Name": "TSplus web portal (older versions: cert.jks)",
          "Kind": "TSplusJks"
        }
      ],
      "Commands": []
    }
  ]
}

A server has only one TSplus, so in practice keep just one of the two TSplus destinations: TSplus for version 15 and later, TSplusJks for older versions.
