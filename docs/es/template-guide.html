RecetaSitio IIS en el mismo servidor

Ejecute CertificateGet como administrador en el servidor IIS.

AjusteValor
Validation methodHTTP — existing web site folder, carpeta del sitio C:\inetpub\wwwroot (la ruta física del sitio)
Key typeRSA 2048
Tras emitirInstall in Windows → Local Machine, y en el Administrador de IIS edite el enlace https del sitio y elija el certificado nuevo

Tras cada renovación instale el certificado nuevo y vuelva a elegirlo en el enlace. Para automatizarlo, use un agente con un comando que actualice el enlace.

RecetaComodín con Cloudflare

AjusteValor
SettingsToken de API de Cloudflare con Zone Read y DNS Edit; Test token
DomainsWildcard, dominio base example.com, Also cover the bare domain marcado
Validation methodDNS — Cloudflare (automatic)
ResultadoUn certificado para *.example.com y example.com; las renovaciones no requieren pasos manuales

Lo mismo funciona con Hostinger, Constellix, DNS Made Easy, Namecheap o acme-dns: solo cambian el método y sus credenciales.

RecetaHAProxy por SFTP

Para un servidor HAProxy donde basta con subir el archivo y recargar. Añada un objetivo de tipo SFTP / SSH y haga clic en el ajuste predefinido HAProxy:

CampoValor predefinido
Remote folder/etc/haproxy/certs
Filescombined → {domain}.pem
Commandhaproxy -c -f /etc/haproxy/haproxy.cfg && systemctl reload haproxy

El usuario debe poder escribir en la carpeta y recargar HAProxy (root, o permisos sudo para el comando). Para varios programas en un servidor, o Cockpit junto a HAProxy, use el agente (plantilla de HAProxy).

agent.jsonLa forma del archivo

agent.json está junto al ejecutable. La parte superior del archivo la escribe install y casi nunca cambia; su trabajo está en Slots. Cada plantilla de abajo es un slot (o un destino) para pegar en esa lista.

{
  "Port": 9443,                         // puerto HTTPS; reinicie el servicio tras cambiarlo
  "ApiKeyHash": "…",                    // lo escriben install / newkey — no lo edite
  "AllowedIps": [ "192.168.1.50" ],     // el PC que ejecuta CertificateGet; [] = cualquiera
  "TlsPfx": "agent-tls.pfx",            // el certificado TLS propio del agente
  "TlsPassword": "…",                   // lo escribe el agente — no lo edite
  "KeepBackups": 5,                     // carpetas de copias fechadas por destino
  "Slots": [
    {
      "Name": "example-com",            // lo que nombra el objetivo de despliegue de la aplicación
      "Description": "…",               // se muestra en la aplicación
      "Destinations": [
        {
          "Name": "…",                  // se muestra en el registro; también nombre de la carpeta de copias
          "Kind": "Files",              // Files (predeterminado), TSplus o TSplusJks
          "Folder": "…",                // se crea si no existe
          "Files": [ { "Source": "fullchain", "FileName": "…" } ],
          "RestartServices": [],        // nombres de servicios de Windows / unidades systemd
          "RestartPrograms": [],        // programas de escritorio de Windows
          "Commands": []                // cmd.exe en Windows, /bin/sh en Linux; {folder} = Folder
        }
      ],
      "Commands": []                    // se ejecutan una vez, después de todos los destinos
    }
  ]
}

Los comentarios son solo para leer

JSON no admite comentarios. Las notas // de arriba explican los campos; el archivo real no debe contenerlas. Las plantillas de abajo son JSON puro y se pueden pegar tal cual.

Después de cada cambio ejecute check. Cada campo se describe en la Referencia.

WindowsNetTalk

Un servidor web NetTalk lee un archivo de certificado y un archivo de clave privada, indicados en la configuración SSL del procedimiento WebServer. Cada instancia suele usar su propia carpeta certificates con <dominio>.crt y <dominio>.key. Escriba fullchain como certificado para que los navegadores reciban el intermedio, key como clave, y reinicie la instancia, porque NetTalk carga los archivos al arrancar.

Ajuste de NetTalkOrigenArchivo de ejemplo
Archivo de certificadofullchaincertificates\www.example.com.crt
Archivo de clave privadakeycertificates\www.example.com.key
ReinicioRestartServices o RestartProgramsNombre del servicio, o la ruta del .exe

Un servicio NetTalk

El nombre del servicio es la columna Name de Get-Service, no el nombre para mostrar.

{
  "Name": "www-example-com",
  "Description": "www.example.com para el servidor web NetTalk",
  "Destinations": [
    {
      "Name": "NetTalk web",
      "Folder": "C:\\Apps\\Web\\certificates",
      "Files": [
        { "Source": "fullchain", "FileName": "www.example.com.crt" },
        { "Source": "key",       "FileName": "www.example.com.key" }
      ],
      "RestartServices": [ "WebServer" ]
    }
  ]
}

Varias instancias de NetTalk, un certificado

Un certificado comodín usado por varios servidores NetTalk es un slot con un destino por instancia, cada uno con los nombres de archivo que esa instancia tiene configurados. El certificado se envía una vez y se escribe tres veces.

{
  "Name": "reddin-wildcard",
  "Description": "*.reddinassessments.com para tres servidores NetTalk",
  "Destinations": [
    {
      "Name": "NetTalk - Assessments",
      "Folder": "C:\\Apps\\Assessments\\certificates",
      "Files": [
        { "Source": "fullchain", "FileName": "reddinassessments.com.crt" },
        { "Source": "key",       "FileName": "reddinassessments.com.key" }
      ],
      "RestartServices": [ "AssessmentsWeb" ]
    },
    {
      "Name": "NetTalk - Portal",
      "Folder": "D:\\Portal\\certs",
      "Files": [
        { "Source": "fullchain", "FileName": "portal.crt" },
        { "Source": "key",       "FileName": "portal.key" }
      ],
      "RestartServices": [ "PortalWeb" ]
    },
    {
      "Name": "NetTalk - Reports",
      "Folder": "D:\\Reports\\certificates",
      "Files": [
        { "Source": "fullchain", "FileName": "reports.reddinassessments.com.crt" },
        { "Source": "key",       "FileName": "reports.reddinassessments.com.key" }
      ],
      "RestartServices": [ "ReportsWeb" ]
    }
  ]
}

NetTalk como programa de escritorio

Cuando el servidor se inicia desde un escritorio con sesión iniciada en lugar de como servicio, reinícielo con RestartPrograms. Cada copia en ejecución se cierra y se vuelve a iniciar con su propia línea de comandos, en el mismo escritorio.

{
  "Name": "api-example-com",
  "Description": "api.example.com, servidor NetTalk iniciado en el escritorio",
  "Destinations": [
    {
      "Name": "NetTalk - API (programa de escritorio)",
      "Folder": "C:\\Apps\\Api\\certificates",
      "Files": [
        { "Source": "fullchain", "FileName": "api.crt" },
        { "Source": "key",       "FileName": "api.key" }
      ],
      "RestartPrograms": [
        { "Path": "C:\\Apps\\Api\\ApiServer.exe", "StopTimeoutSeconds": 30 }
      ]
    }
  ]
}

Si el programa debe permanecer oculto y nadie ha iniciado sesión, añada "StartIn": "Background". Los detalles están en RestartPrograms.

LinuxHAProxy

HAProxy quiere el certificado, la cadena y la clave en un solo archivo PEM, que es el origen combined. Apunte la línea bind a la carpeta, y HAProxy carga cada archivo de ella y elige uno por SNI.

frontend https-in
    bind :443 ssl crt /etc/haproxy/certs/ alpn h2,http/1.1
    bind :80
    http-request redirect scheme https unless { ssl_fc }
    default_backend web

Un certificado

{
  "Name": "example-com",
  "Description": "HAProxy en lb01",
  "Destinations": [
    {
      "Name": "HAProxy",
      "Folder": "/etc/haproxy/certs",
      "Files": [
        { "Source": "combined", "FileName": "example.com.pem" }
      ],
      "Commands": [ "haproxy -c -f /etc/haproxy/haproxy.cfg && systemctl reload haproxy" ]
    }
  ]
}

El comando comprueba toda la configuración con el archivo nuevo antes de recargar. Si la comprobación falla, la recarga no se ejecuta, HAProxy sigue sirviendo con el certificado que ya tenía y la aplicación muestra el error. reload mantiene las conexiones abiertas; evite RestartServices: ["haproxy"].

Varios certificados en la misma carpeta

Cada certificado es su propio slot con su propio nombre de archivo. Cada certificado de la aplicación recibe un objetivo que apunta a su slot.

"Slots": [
  {
    "Name": "example-com",
    "Destinations": [
      { "Name": "HAProxy", "Folder": "/etc/haproxy/certs",
        "Files": [ { "Source": "combined", "FileName": "example.com.pem" } ],
        "Commands": [ "haproxy -c -f /etc/haproxy/haproxy.cfg && systemctl reload haproxy" ] }
    ]
  },
  {
    "Name": "example-org",
    "Destinations": [
      { "Name": "HAProxy", "Folder": "/etc/haproxy/certs",
        "Files": [ { "Source": "combined", "FileName": "example.org.pem" } ],
        "Commands": [ "haproxy -c -f /etc/haproxy/haproxy.cfg && systemctl reload haproxy" ] }
    ]
  }
]

LinuxCockpit

Cockpit toma su certificado de /etc/cockpit/ws-certs.d. Usa el último archivo .cert o .crt en orden alfabético; un archivo .cert contiene la cadena y la clave juntas, y un archivo .crt necesita un archivo .key con el mismo nombre. La clave debe ser legible por el grupo cockpit-ws.

Reemplazar el certificado que Cockpit ya usa

Si ya hay un certificado, por ejemplo reddinassessments.cert, sobrescríbalo con combined. El agente conserva su propietario, grupo, modo y etiqueta SELinux, y el comando los vuelve a establecer para un primer despliegue.

{
  "Name": "Cockpit",
  "Folder": "/etc/cockpit/ws-certs.d",
  "Files": [
    { "Source": "combined", "FileName": "reddinassessments.cert" }
  ],
  "Commands": [ "chgrp cockpit-ws {folder}/reddinassessments.cert && chmod 640 {folder}/reddinassessments.cert && restorecon -F {folder}/reddinassessments.cert ; systemctl reset-failed cockpit.socket cockpit ; systemctl restart cockpit.socket ; systemctl try-restart cockpit" ]
}

Añadir un certificado junto al autofirmado

Si no, escriba fullchain y key como 90-letsencrypt.crt y 90-letsencrypt.key. Van después de 0-self-signed.cert de Cockpit en orden alfabético, así que Cockpit los elige.

{
  "Name": "Cockpit",
  "Folder": "/etc/cockpit/ws-certs.d",
  "Files": [
    { "Source": "fullchain", "FileName": "90-letsencrypt.crt" },
    { "Source": "key",       "FileName": "90-letsencrypt.key" }
  ],
  "Commands": [ "chgrp cockpit-ws {folder}/90-letsencrypt.key && chmod 640 {folder}/90-letsencrypt.key && restorecon -F {folder}/90-letsencrypt.* ; systemctl reset-failed cockpit.socket cockpit ; systemctl restart cockpit.socket ; systemctl try-restart cockpit" ]
}

Qué hace el comando

PartePor qué
chgrp cockpit-ws … && chmod 640 …La clave debe ser legible por cockpit-tls, que se ejecuta como cockpit-ws.
restorecon -F …Restablece la etiqueta SELinux. No está instalado en Debian/Ubuntu; el ; que le sigue permite que el resto se ejecute igualmente.
systemctl reset-failed cockpit.socket cockpitBorra el límite de arranques de systemd tras fallos anteriores, para que el reinicio no se rechace.
systemctl restart cockpit.socketCockpit se activa por socket; reiniciar el socket hace que la siguiente conexión cargue el certificado nuevo.
systemctl try-restart cockpitReinicia el servicio solo si está en ejecución, y termina con código de salida 0 para que el paso tenga éxito.

Para ver qué certificado usará Cockpit:

sudo /usr/lib/cockpit/cockpit-certificate-ensure --check      # Debian / Ubuntu
sudo /usr/libexec/cockpit-certificate-ensure --check         # RHEL / Rocky / Alma / Fedora

WindowsTSplus

TSplus tiene dos formas de recibir un certificado, según la versión. Ambas son un destino con un Kind y sin archivos; el agente conoce las rutas.

KindVersión de TSplusQué hace el agente
TSplus15 y posterioresEscribe un PFX temporal y certpassword.txt, ejecuta C:\Program Files (x86)\TSplus\UserDesktop\files\cert\CertificateManager.exe /add <pfx> y elimina ambos.
TSplusJksVersiones que usan cert.jksRespalda y reemplaza C:\Program Files (x86)\TSplus\Clients\webserver\cert.jks (contraseña secret, cadena completa) y luego ejecuta UserDesktop\files\AdminTool.exe /webrestart.

TSplus 15 y posteriores

{
  "Name": "tsplus-example-com",
  "Description": "remote.example.com para el portal web de TSplus",
  "Destinations": [
    { "Name": "Portal web de TSplus", "Kind": "TSplus" }
  ]
}

TSplus antiguo con cert.jks

{
  "Name": "tsplus-example-com",
  "Description": "remote.example.com para un TSplus antiguo (cert.jks)",
  "Destinations": [
    { "Name": "Portal web de TSplus", "Kind": "TSplusJks" }
  ]
}

La contraseña JKS viene de Settings de la aplicación (JKS keystore password). Déjela en secret; TSplus espera ese valor.

TSplus instalado en otra ubicación

{ "Name": "TSplus (15+) en D:",   "Kind": "TSplus",    "TsplusCertFolder": "D:\\TSplus\\UserDesktop\\files\\cert" }
{ "Name": "TSplus (jks) en D:",   "Kind": "TSplusJks", "TsplusFolder": "D:\\TSplus" }

check confirma que CertificateManager.exe o la carpeta Clients\webserver están donde indica el destino.
